## Безопасность и конфиденциальность (TO-BE)

## 1. Перечень данных, подлежащих защите

### 1.1 Классификация данных

| Категория данных | Примеры | Уровень чувствительности |
|------------------|---------|--------------------------|

## 3. Архитектурные меры защиты

### 3.1 Шифрование данных

- **At Rest**
    - Шифрование баз данных и файлов (AES-256)
    - Хранение ключей отдельно от данных (KMS / Vault / HSM)

- **In Transit**
    - Использование TLS для всех внутренних и внешних соединений
    - Запрет передачи данных в открытом виде

---

### 3.2 Обфускация и маскирование

Обфускация применяется на уровне отображения данных и зависит от роли пользователя.

Примеры:
- Телефон: `+7 *** ***-12-34`
- Email: `i***@mail.ru`
- Платёжные данные: `**** **** **** 1234`

---

### 3.3 Обезличивание данных

Обезличивание используется для аналитики и отчётности.

Методы:
- замена ФИО на surrogate key (`Patient_ID`)
- агрегация данных (возрастные группы)
- исключение прямых идентификаторов

---

## 4. Механизм тегирования данных

### 4.1 Цель тегирования

Тегирование данных используется для:
- централизованного управления доступом
- автоматического применения мер защиты
- контроля потоков данных

---

### 4.2 Модель тегов данных

#### 4.2.1 Теги чувствительности

| Тег | Описание |
|----|----------|
| `PUBLIC` | Общедоступные данные |
| `INTERNAL` | Внутренние данные |
| `CONFIDENTIAL` | Персональные данные |
| `SENSITIVE` | Медицинские данные |
| `CRITICAL` | Платёжные и особо чувствительные данные |

---

#### 4.2.2 Теги типа данных

| Тег | Описание |
|----|----------|
| `PII` | Персональные данные |
| `PHI` | Медицинские данные |
| `PAYMENT` | Платёжные данные |
| `TECH` | Технические данные |

---

#### 4.2.3 Теги обработки и защиты

| Тег | Назначение |
|----|-----------|
| `ENCRYPT_AT_REST` | Обязательное шифрование при хранении |
| `ENCRYPT_IN_TRANSIT` | Шифрование при передаче |
| `MASK_ON_VIEW` | Маскирование при отображении |
| `ANONYMIZE_FOR_ANALYTICS` | Обезличивание |
| `RESTRICTED_ACCESS` | Доступ по ролям |

---

field: phone_number
